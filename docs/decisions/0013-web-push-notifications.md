# ADR-0013: התראות Web Push לאוסף על הזמנה חדשה (SW מינימלי בלי cache)

**סטטוס:** מאושר (2026-11-09) · **תאריך:** 2026-11-09 · **מחליט:** אני (המפתח), לבקשת יואל
**מעדכן את:** ADR-0006 (מוסיף Service Worker מינימלי ל-push בלבד, בלי cache); spec §1, ש10.

## הקשר
- ב-ADR-0006 וב-spec ש10 הוחלט להתחיל בלי התראות ובלי Service Worker, כדי לא להוסיף שכבת cache שעלולה להגיש ליואל גרסה ישנה אחרי deploy.
- יואל מבקש לקבל התראה בטלפון כשנכנסת הזמנה חדשה מהטופס הציבורי, כדי שלא יצטרך להיכנס לאפליקציה ולבדוק ידנית אם נכנסו הזמנות.
- באייפון (מ-iOS 16.4 ומעלה) ובאנדרואיד, Web Push עובד מתוך PWA שמותקן למסך הבית (כבר מוגדר ב-ADR-0006), בחינם וללא שירות צד שלישי בתשלום, באמצעות תקן Web Push ו-VAPID.

## החלטה
1. **Service Worker מינימלי ל-Push בלבד (`apps/web/public/sw.js`):**
   - מאזין רק לשני אירועים: `push` (הצגת ההתראה) ו-`notificationclick` (פתיחה או מיקוד של `/app/orders`).
   - **אפס מאזיני `fetch` ואפס שימוש ב-Cache Storage.** ה-Service Worker לעולם לא מיירט בקשות רשת ולא שומר קבצים מקומית, ולכן אין שום סיכון של הגשת גרסה ישנה אחרי deploy (החשש שבגללו נפסל SW מלא ב-ADR-0006).
   - נרשם רק באפליקציית האוסף (`/app/*`). הלקוחות בטופס הציבורי וב-`/o/<token>` לא רואים שום שינוי.
2. **Web Push ב-VAPID (חינם, בלי ספק חיצוני):**
   - השרת חותם ושולח התראות ישירות ל-push service של הדפדפן (Apple / Google / Mozilla) באמצעות VAPID (`web-push`).
   - אוסף מנויים (`pushSubscriptions`) ב-MongoDB שומר את ה-`endpoint` והמפתחות (`p256dh`, `auth`) של המכשירים שיואל הפעיל בהם התראות (מאונדקס לפי `endpoint` ייחודי).
3. **מתי נשלחת התראה ומה כתוב בה:**
   - רק כשנכנסת הזמנה חדשה מהטופס הציבורי (`POST /api/orders`). הזמנה שיואל מוסיף בעצמו (`POST /api/collector/orders`) לא שולחת התראה לעצמו.
   - תוכן ההתראה בעברית: כותרת `"הזמנה חדשה — לתת עוד"`, וגוף עם שם הלקוח, כתובת (רחוב ומספר בית) וכמות בקבוקים משוערת, וקישור ל-`/app/orders`.
   - השליחה היא **best-effort**: כישלון בשליחת Push נרשם בלוג בלבד ולעולם לא מכשיל את יצירת ההזמנה של הלקוח. מנוי שהחזיר `404` או `410` (בוטל או הוסר במכשיר) נמחק אוטומטית מהמסד.
4. **הפעלה באפליקציית האוסף (`/app/orders`):**
   - במסך ההזמנות מופיע כפתור להפעלת/כיבוי התראות במכשיר הנוכחי (דורש לחיצת משתמש לבקשת הרשאה מהדפדפן, כנדרש ב-iOS).
   - נתיבים מוגנים (`requireCollector`): `GET /api/collector/push/config`, `POST /api/collector/push/subscribe`, `POST /api/collector/push/unsubscribe`.
5. **הגדרות סביבה אופציונליות (`apps/api/.env`):**
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:...` או `https://...`).
   - אם המשתנים אינם מוגדרים, השרת עולה כרגיל בלי התראות ו-`GET /api/collector/push/config` מחזיר `{ enabled: false }`.

## חלופות שנדחו
- **הודעת WhatsApp ליואל על כל הזמנה:** דורש WhatsApp Cloud API אוטומטי בתשלום ורישום עסק ב-Meta (ADR-0003), בניגוד לעיקרון אפס עלות.
- **אימייל ליואל:** דורש שירות שליחת מיילים (SMTP / API חיצוני) ופחות נוח מהתראה שקופצת בטלפון ופותחת בלחיצה את מסך ההזמנות.
- **PWA מלא עם offline cache:** אין צורך בעבודה בלי רשת (ADR-0006), ו-cache של קבצים ב-Service Worker עלול להשאיר את יואל עם גרסה ישנה אחרי deploy.

## השלכות
- 👍 התראה מיידית בחינם לטלפון של יואל (אייפון מותקן למסך הבית או אנדרואיד/מחשב) בלי ספק צד שלישי בתשלום.
- 👍 בלי `fetch` ובלי cache ב-SW: אפס סיכון לגרסה ישנה תקועה אצל יואל אחרי deploy.
- 👍 אופציונלי לגמרי: סביבת פיתוח ובדיקות עובדות בלי להגדיר מפתחות VAPID, ומאחורי ממשק `PushNotifier` עם `FakePushNotifier` לבדיקות.
- 👎 באייפון, Web Push עובד רק כשהאפליקציה הותקנה למסך הבית (כבר מתועד ב-ADR-0006) ומ-iOS 16.4 ומעלה.

**עלות:** 0.
