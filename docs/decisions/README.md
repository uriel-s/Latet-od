## מה ה-ADRs משנים ב-spec
- **מודל הנתונים מצטמצם:** בלי `users`, `customers`, `settings`, ובלי שדה `location` בהזמנה. נוספים
  `address.nearStreetCode`, יומן `messages` בהזמנה, ואוסף טכני `loginAttempts` (TTL).
- **בלי סטטוס "כתובת לבדיקה":** אין geocoding בזמן ריצה. במקומו, תג "בלי מיקום".
- **פוטר:** "© OpenStreetMap contributors".
- **התקנה למסך הבית** (ADR-0006, 2026-10-20): את אפליקציית האוסף אפשר להוסיף למסך הבית (PWA בלי service worker). הלקוחות נשארים "אתר בלי התקנה", ו-native עדיין מחוץ ל-MVP.
- **ניווט לעצירה הבאה** (ADR-0007, 2026-10-21): בראש מסך המסלול נוספים "נווט לעצירה הבאה" (Waze) ו"כל המסלול ב-Google Maps" (קישור, בלי `origin`). `DROP_OFF_ADDRESS` (טקסט ציבורי) עובר ל-`packages/shared`.
- **מחיקת הזמנה** (ADR-0008, 2026-10-21): "מחיקת ההזמנה" במסך העריכה, רק להזמנה `waiting` או `cancelled` שאינה בסבב (`canDeleteOrder`). מחיקה קשה, `DELETE /api/collector/orders/:id`.
- **חלון שעות להוצאה** (ADR-0009, 2026-10-21): בסבב נוסף `pickupFrom` אופציונלי לצד `pickupBy`. ההודעה, עמוד הלקוח ומסך הסבבים אומרים "בין השעות X ל-Y". בלי מיגרציה.
- **טופס ועמוד הזמנה באנגלית** (ADR-0010, 2026-11-04): `/en` ו-`order.lang`. עמוד הלקוח וההודעות בשפת ההזמנה, `nameEn` לרחובות. אפליקציית האוסף ו-Open Graph נשארים בעברית.
- **בלי אישור מהלקוח** (ADR-0012, 2026-11-07): תכנון סבב מעביר את ההזמנות ישר ל"בסבב" (`confirmed`), ו"התחל מסלול" לא מוציא אף אחד. אין כפתור "כן, אוציא" ואין "אישר בשיחה או בהודעה". "ממתינה לאישור" ו"לא אישר בזמן" נשארים רק לנתונים ישנים. עם שתי שעות, בעמוד הלקוח: "נא להוציא את הבקבוקים עד השעה X. נגיע בין השעות X ל-Y." הודעת ה-WhatsApp (עדכון 2026-11-11) כותבת יום בשבוע ושתי שורות: "נא להוציא את הבקבוקים החוצה עד השעה X." ו"נגיע לאסוף בין השעות X עד Y."
- **שפה עיצובית** (ADR-0011, 2026-11-04): פלטת "שחר" מחליפה את צבעי המיתוג של spec §7. Heebo מקומי, אייקוני SVG בקוד, מצב כהה אוטומטי. כפתור "נווט" לעצירה הבאה עובר לתוך כרטיס העצירה הנוכחית (ההתנהגות של ADR-0007 לא משתנה). `collected` נשאר סופי: אין "ביטול" אחרי "אספתי".
- **התראות על הזמנה חדשה** (ADR-0013, 2026-11-09): Web Push (VAPID, חינם) ליואל כשנכנסת הזמנה חדשה מהטופס הציבורי (`POST /api/orders`). נוסף Service Worker מינימלי (`apps/web/public/sw.js`) שמטפל ב-`push` וב-`notificationclick` בלבד (פותח את `/app/orders`), בלי `fetch` ובלי cache כדי שלא תוגש גרסה ישנה אחרי deploy (מעדכן את ADR-0006 ואת ש10). אופציונלי: תלוי ב-`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
